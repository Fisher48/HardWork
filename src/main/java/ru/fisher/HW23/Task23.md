### Избавляемся от зависимости от зависимостей - 2

#### Пример 1: Зависит ли админ-панель создания товара от редактора текста WYSIWYG (Quill)

Проект использует Quill как редактор текста в поле для ввода описания товара.

**_Семантика_**
- Зависимость сборки:  
  Здесь зависимости нет, подгружается скрипт из вне по CDN.


- Зависимость времени выполнения:  
  Здесь есть зависимость насколько быстро браузер загрузи скрипт и инициализирует редактор.


- Функциональные требования:
  Зависимость есть. Редактор жестко встроен в форму создания товара.  
  При замене на другой редактор потребуется переписывать код инициализации и адаптировать сохранение HTML-контента.

**_Ключевые свойства:_**  
Зависит ввод описания товара, если Quill не доступен, то нет возможности ввести описание товара.  
Форматирование текста в формате HTML зависит от Quill.
Доступность редактора от внешних сервисов.

**_Пространство допустимых значений:_**  
Должна сохранятся совместимость при изменении версии редактора.
Добавление новых возможностей для редактирования текста не должно ломать предыдущие функции.
Нельзя удалять редактор если нет запасного поля textarea.


#### Пример 2: Зависит ли приложение от PostgreSQL

Проект использует PostgreSQL как основную БД.

**_Семантика_**
- Зависимость сборки:
  Отсутствует так как БД разворачивается отдельно от приложения в своем контейнере.
  Присутствует связь через postgresql driver.
  Зависимость в pom.xml


- Зависимость времени выполнения:
  Существует зависимость. Если контейнер с БД будет долго запускаться, то приложение будет ожидать успешного запуска БД, бзе него приложение не запуститься.


- Функциональные требования:
  Есть зависимость. Зависит от диалекта SQL, при переходе на другую БД возможно появление ошибок в синтаксисе.
  В частности инициализация БД посредством Flyway, в котором можно выбрать на каком БД мы пишем запросы.
  Нужно это учитывать.

**_Ключевые свойства:_**  
Безопасность: Создается специальный профиль для админа по управлению в БД, во избежания несанкционированного доступа.  
Доступность: Разграничение ролей пользователей в БД.
Производительность: Оптимизация запросов, избежание не нужных соединений в запросе. Это ускоряет запросы к БД.
Кеширование часто используемых запросов, которые не подвержены изменению.

**_Пространство допустимых значений:_**  
Допустимо менять версии PostgreSQL, должна быть обратная совместимость.
Нельзя менять структуру таблиц, во избежание проблем с запросами.
Нельзя менять драйвер БД без изменения самой БД.

#### Пример 3: Зависит ли сервис генерации поездок от внешнего OpenRouteService

Проект использует OpenRouteService для генерации маршрутов для каждого автомобиля предприятия.
А также для обратного и прямого геокодирования по адресу.

**_Семантика_**
- Зависимость сборки:  
  Не зависит.
  Существует API_KEY для обращения к данному внешнему сервису, но на этапе сборки он никак не влияет и не компилируется.


- Зависимость времени выполнения:  
  Зависимость есть, если сервис не доступен, то поездка не сгенерируется.
  Или адрес не будет выведен пользователю по координатам.


- Функциональные требования:
  Зависимость есть. Данный сервис прописал четко в коде проекте и если потребуется использовать другой, потребуется переписывать код.
  Либо нужно было сделать абстракцию по выбору сервиса геокодирования и прописывать селектор.
  Или полностью переписывать под другой сервис.

**_Ключевые свойства:_**  
Точность: Геокодирование зависит от координаты чем точнее, тем конкретнее будет адрес, а не просто улица без дома.  
Надежность: Не будет работать, если сервис не доступен или превышен лимит запросов.  
Производительность: Ограничена лимитом запросов (платное/бесплатное) по времени.

**_Пространство допустимых значений:_**  
Возможно добавление дополнительных полей для получения в запросе, скорость движения, высота и т.д.
Есть строгий формат, которого нужно придерживаться lat lon, порядок может сломать работу.
Ключ должен быть один и привязан к пользователю.

#### Пример 4: Зависит ли сервис парсинга Excel файлов от библиотеки Apache POI

Проект использует Apache POI для парсинга товаров и цен при добавлении или обновлении.

**_Семантика_**
- Зависимость сборки:
  Зависит если библиотека не загрузится, то сервис не сможет функционировать, pom.xml


- Зависимость времени выполнения:
  В рантайме POI читает Excel файл и строит объекты. Ошибки формата, большие файлы могут вызвать исключения.
  Зависит от того насколько большой файл, или как прописан импорт товаров, это влияет на время выполнения чтения Excel файла.


- Функциональные требования:
  Импорт цен зависит от структуры Excel (колонки, форматы). 
  Сменить POI на другую библиотеку без изменения кода невозможно.

**_Ключевые свойства:_**  
Производительность: Насколько правильно прописан импорт (батчи, запросы и т.д), настолько будет быстро выполнен парсинг
Форматы: Доступны определенные форматы xsl, xslx.
Стабильность: Если файл будет слишком велик импорт может упасть (для этого указано ограничение в 10 мб)

**_Пространство допустимых значений:_**  
Версия библиотеки должна сохранять обратную совместимость.
Приложение должно корректно обрабатывать ошибки парсинга (невалидные строки, поврежденные файлы) и не падать целиком. 
Обновление POI должно сохранять совместимость с текущим кодом.
