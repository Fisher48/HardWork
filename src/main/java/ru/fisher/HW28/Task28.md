### Формализуем многослойную (многоуровневую) архитектуру

Я, как обычно, рассмотрю свой проект **_ToolsMarket_** на предмет МУРА.

В целом в проекте можно проследить такие уровни:
1. Представление (UI)
2. Контролеры
3. Сервисы
4. Репозитории
5. БД

Это в большинстве своем - классические уровни веб-приложения написанного на Spring.
```
-----------------
      UI         |
      |          |
      |          |
      V          |
  Contoller      |
      |          |
      |          |
      V          |
   Service       |
      |          |
      |          |
      V          |
  Repository     |
      |          |
      |          |
      V          |
   Database      |
------------------ 
```
Все идет друг за другом, как и должно быть. Пользователь взаимодействует с UI, далее контроллеры принимают запросы, 
конвертируют в нужный формат и передают информацию в сервисы, 
где основная бизнес-логика обработки запросов уходит в репозитории. И уже там напрямую в БД. Здесь никто друг от друга не зависит.

Граф ацикличный нет никаких зацикливаний, тем более что Spring на минимальном уровне это проверяет и не дает запустить приложение,
если существуют циклические зависимости типа (А-В-А).

**_Вывод:_**  
Обычно когда мы уже глубоко в проекте, особенно когда в начале ты только начинаешь сам, без роли какого-либо руководителя или сеньора, то легко упустить архитектуру
и базовые вещи. В частности и то что есть многоуровневая архитектура и ее нужно придерживаться как базы, слой за слоем не смешивая и не перескакивая между уровнями.
Рассматривая структуру проекта в виде направленного ацикличного графа заметил что я подсознательно некоторые вещи все же понимал и делал правильно. 
Местами из-за спешки можно напутать слои или связать напрямую пропустив слои (например обратиться в контроллере к репозиторию, минуя слой сервиса). 
Но уже когда набита рука, ты сразу понимаешь что так нельзя. 
А самое главное, что соблюдение многоуровневой архитектуры облегчает переиспользование кода и соответственно изолированное тестирование слоев.
